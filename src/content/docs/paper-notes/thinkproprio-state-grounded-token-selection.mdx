## 한 줄 요약

ThinkProprio는 proprioception을 action head에 늦게 주입하는 대신 VLM vocabulary token으로 이산화하고, language와 함께 **VLM 이전의 visual patch 선택 query**로 사용해 CALVIN에서는 100개 중 평균 12개 token만 남기면서 FLOWER보다 긴 chain 성능과 latency를 함께 개선한다.

## 문제의식

대부분의 VLA는 현재 robot state를 다음 중 하나로 처리한다.

- proprioception을 action expert에 late conditioning한다.
- MLP로 projection해 VLM 또는 action expert에 넣는다.
- state를 생략하고 vision-language representation만 action에 전달한다.

이 설계에서는 proprioception이 “어떤 action을 낼지”에는 영향을 줄 수 있어도, **instruction을 현재 embodiment에 맞게 grounding하거나 어떤 visual evidence를 볼지**에는 관여하지 못한다. 논문의 질문은 단순하다.

> Robot state는 action generation의 수동 조건이어야 하는가, 아니면 instruction grounding과 visual attention을 이끄는 능동 query여야 하는가?

Table 7의 통제 실험이 이 framing의 핵심 근거다. 같은 backbone·action head·data·training budget에서 state가 없는 FLOWER는 Avg. Len. 4.44이고, action head에 MLP/AdaLN으로 늦게 넣어도 4.44다. 반면 VLM vocabulary token으로 만들어 VLM에 넣으면 4.48이 된다. 즉 논문이 보여주는 것은 “proprioception을 추가하면 좋아진다”가 아니라, **어떤 representation으로 어느 지점에 넣는지가 중요하다**는 것이다.

## Method

![ThinkProprio 전체 architecture와 language/proprioception selector branch](/thinkproprio/figure-2-architecture.png)

*Figure 2. 두 branch가 visual token에 투표하고 hard union으로 선택한 뒤, global context token과 함께 VLM 및 flow action head에 전달한다.*

### 1. Proprioception을 VLM vocabulary ID로 바꾸기

각 scalar state `q_t,k`를 shared clipping range `[q_min, q_max]`로 자르고 `B`개 uniform bin으로 양자화한다. 기본값은 normalized state에 대해 `[-3,3]`, `B=256`이다.

```text
b_t,k = floor((clip(q_t,k, q_min, q_max) - q_min)
              / (q_max - q_min) * (B - 1))
tau_t,k = V - 1 - b_t,k
H_q = Embed(tau_t)
```

여기서 `V`는 VLM vocabulary size다. 중요한 점은 `tau`가 language tokenizer가 출력한 text token이 아니라, vocabulary 뒤쪽 ID를 **discretized state value의 alias**로 재사용한 것이라는 점이다.

- 새 embedding parameter가 필요 없다.
- text와 같은 pretrained lookup pathway를 사용한다.
- 논문에 사용한 prompt에서는 language token과 state token ID가 충돌하지 않도록 reverse indexing한다.
- 그러나 이 “비충돌”은 해당 prompt 집합에 대한 확인이지 vocabulary 의미 보존에 대한 일반적인 보장은 아니다.

### 2. Branch-specific vote matrix

visual tokens `H_v`와 guidance tokens `G_lang=H_l`, `G_prop=H_q`를 RMSNorm한다. 각 visual token은 먼저 guidance token을 attend해 자신에게 관련된 guidance-conditioned query `Q_omega`를 만들고, 그 query로 모든 visual token 후보를 다시 score한다.

```text
Q_omega = softmax(H_v G_omega^T / sqrt(D)) G_omega
S_omega = RMSNorm(Q_omega) H_v^T / sqrt(D)
```

`S_omega`는 `N_v × N_v` vote matrix다. 행 `i`는 투표하는 visual token, 열 `j`는 유지 후보 visual token이다. 단일 top-down saliency vector가 아니라, **visual context를 본 각 token이 후보에게 투표**하는 구조다.

### 3. Hard selection과 noisy-OR straight-through gradient

학습 시 score에 Gumbel noise를 더하며 scale `alpha`를 1.0에서 0.01까지 cosine annealing한다. 각 row는 argmax 하나에 투표하고, 한 표라도 받은 token을 branch mask에 남긴다. 두 branch의 최종 mask는 union이다.

```text
z_omega[i] = argmax_j S_omega[i,j]
m_omega[j] = 1[어떤 i가 j에 투표]
m[j] = m_lang[j] OR m_prop[j]
```

hard OR는 미분할 수 없으므로 backward에는 noisy-OR를 쓴다. row softmax probability가 `P_omega[i,j]`일 때 token `j`가 적어도 한 표를 받을 확률은 다음과 같다.

```text
rho_omega[j] = 1 - product_i(1 - P_omega[i,j])
rho[j] = 1 - (1-rho_lang[j])(1-rho_prop[j])
w[j] = m[j] + rho[j] - stop_gradient(rho[j])
```

forward 값은 정확히 hard mask `m`, gradient만 `rho`를 따른다. 부록 A는 noisy-OR가 boundary agreement, monotonic gradient, `[0,1]` boundedness, 복수 vote의 누적을 동시에 만족한다고 설명한다. 다만 row와 branch의 조건부 독립은 정확하지 않으므로 확률적 해석은 approximation이다.

### 4. Complementarity와 global context

두 branch가 같은 patch만 고르는 collapse를 막기 위해 row-aggregated selection distribution 사이 cosine similarity에 margin `gamma=0.75`를 둔 diversity loss를 사용한다.

한편 aggressive pruning은 local vote를 못 받은 scene-level 정보를 지울 수 있다. 이를 보완하려고 selection 전 visual token 전체의 mean을 linear projection한 global context token `H_ctx` 하나를 항상 붙인다.

### 5. VLM과 action flow

선택된 token과 global/state/language token을 다음 순서로 VLM에 전달한다.

```text
C = f_VLM([H_v_selected; H_ctx; H_q; H_l])
```

action head는 noisy action chunk와 flow time `T`, conditioning `C`를 받아 velocity를 예측한다. 선형 interpolation `a^T=(1-T)a+T epsilon`에서 target velocity는 `epsilon-a`이고, 최종 loss는 다음 두 항이다.

```text
L = L_flow_matching + lambda_div * L_div
```

## Model Architecture

| 구성 | v2 PDF 설정 | 역할 |
| --- | --- | --- |
| VLM | Florence-2-Large, fine-tuned | visual/language/state token context encoder |
| selector | language/prop vote matrices + hard union | VLM 이전에 action-relevant patch 선택 |
| context token | full visual-token mean + learned linear projection | pruning으로 잃는 coarse scene context 보존 |
| action generator | rectified-flow Diffusion Transformer | continuous action chunk 생성 |
| DiT hidden/layers/heads | 1024 / 18 / 16 | action sequence processing |
| conditioning | action token이 `C`에 cross-attention, flow time은 global AdaLN | token-level context와 diffusion time 결합 |
| dropout | attention/residual/MLP 0.1, VLM output token dropout 0.1 | regularization |
| action chunk | 10 actions, 4 flow sampling steps | 10 environment steps마다 replanning |
| scale | Table 10 기준 약 0.95B | FLOWER와 같은 Florence-2-Large 계열 비교 |

FLOWER가 100개 visual token을 dense cross-attention context로 넘기는 데 비해, ThinkProprio는 CALVIN에서 평균 12개만 넘긴다. selector 자체는 `O(N_v²D)`지만 현재 `N_v=100` 또는 34라서 0.1 ms에 그친다. sequence가 짧아져 VLM뿐 아니라 cross-attention action head도 싸지는 것이 latency 감소의 주된 원인이다.

## Training Recipe

| 항목 | 값 |
| --- | --- |
| training | selector, Florence backbone, action head end-to-end |
| optimizer | AdamW |
| learning rate | `2e-5` |
| betas | `(0.9, 0.95)` |
| weight decay | 0.05, norm/bias에는 0 |
| batch / hardware | per-GPU 8, GPU 1개 |
| total steps | 50,000 (`max_epochs=50`, `limit_train_batches=1000`) |
| LR schedule | tri-stage: warmup 5% → hold 10% → cosine decay 85% |
| warmup/final LR | `0.1×lr`에서 시작, `0.5×lr`로 종료 |
| precision | bf16-mixed |
| EMA | decay 0.999, 평가에 EMA weight 사용 |
| Gumbel scale | 1.0 → 0.01 |
| diversity | `lambda_div=5e-4`, margin `gamma=0.75` |
| proprio tokenization | 256 bins, clipped normalized range `[-3,3]` |

GPU 모델과 training time은 학습 표에 보고되지 않는다. latency/VRAM profiling은 별도로 단일 RTX 4090, bf16, two-view, CUDA synchronization, 1,000 inference steps 조건이다.

## Experiments and Results

### Main simulation 및 real-world 결과

![CALVIN, LIBERO, 14개 real-world task의 v2 주요 결과](/thinkproprio/tables-2-3-results.png)

*Tables 2–3. Simulation 결과는 특별한 표시가 없으면 5 seeds 평균이다. Real-world 결과는 task당 20 trials의 성공 횟수다.*

#### CALVIN ABC→D

| Method | LH-1 | LH-2 | LH-3 | LH-4 | LH-5 | Avg. Len. |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| FLOWER | **99.3** | **96.0** | 90.3 | 82.3 | 75.5 | 4.44 |
| ThinkProprio | 98.9 | 95.4 | **91.6** | **86.4** | **79.1** | **4.52** |

ThinkProprio는 처음 두 단계에서는 FLOWER보다 각각 0.4, 0.6 point 낮고, LH-3 이후 앞선다. LH-5 failure는 24.5%에서 20.9%로 줄어 상대 failure reduction이 약 14.7%다. 이것은 state-conditioned selection이 configuration drift가 누적되는 긴 chain에 더 유리하다는 저자의 해석과 맞지만, mechanism을 직접 causal하게 증명하는 실험은 아니다.

#### LIBERO

| Method | Spatial | Object | Goal | Long | Avg. |
| --- | ---: | ---: | ---: | ---: | ---: |
| FLOWER | 97.5 | 99.1 | 96.1 | 94.9 | 96.9 |
| LightVLA | **98.4** | 98.4 | **98.2** | 94.6 | 97.4 |
| ThinkProprio | **98.4** | **99.2** | 98.0 | **95.2** | **97.7** |

ThinkProprio의 평균은 가장 높지만 LightVLA와의 차이는 0.3 point다. Spatial은 공동 최고, Goal은 LightVLA보다 0.2 point 낮다. “전 suite에서 압도적”이 아니라 Object/Long과 평균에서 소폭 우세하다고 읽어야 한다.

#### Real world

ThinkProprio는 **249/280 = 88.9%**, FLOWER는 **226/280 = 80.7%**다. 14 tasks 중 13개에서 같거나 높고, 예외는 Banana Plate→Basket의 17/20 대 19/20이다. Drawer open/close는 각각 18/20 대 16/20이다. 다만 동일한 120분 data에서 비교했는지 외에 trial randomization과 confidence interval은 제공되지 않는다.

### Efficiency

| Method | visual tokens | latency / env step | peak VRAM | CALVIN Avg. Len. |
| --- | ---: | ---: | ---: | ---: |
| OpenVLA | 256 | 164 ms | 14,574 MB | 3.27 |
| π0 | 256 | 104 ms | 6,692 MB | 2.01 |
| π0.5 | 256 | 138 ms | 7,038 MB | 2.38 |
| FLOWER | 100 | 52 ms | 1,848 MB | 4.44 |
| ThinkProprio | **12** | **22 ms** | 1,899 MB | **4.52** |

FLOWER 대비 latency는 52→22 ms로 **57.7% 감소**한다. VRAM은 selector parameter 때문에 51 MB, 약 2.8% 증가한다. Table 13의 breakdown은 다음과 같다.

| Benchmark | tokens | vision | selector | VLM | action | total |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| CALVIN ABC→D | 12/100 | 5.8 | 0.1 | 0.9 | 15.4 | 22.2 ms |
| LIBERO | 7.8/34 | 6.5 | 0.1 | 1.1 | 16.1 | 23.8 ms |

selector overhead가 매우 작은 반면 action head가 여전히 지배적이다. 따라서 22 ms를 곧바로 45 Hz closed-loop control이라고 해석하면 안 된다. 논문은 10-step chunk를 10 environment steps마다 갱신하며 실제 environment/control Hz를 보고하지 않는다.

## Appendix Notes

### Appendix A — Noisy-OR

- hard Boolean union의 expected mask라는 확률적 유도를 제공한다.
- max, sum, mean surrogate와 비교해 noisy-OR만 네 property를 모두 만족한다고 정리한다(Table 8).
- noisy-OR는 deployed forward path에 들어가지 않고 straight-through backward signal에만 쓰인다.
- 현재 step에서 drop된 token은 VLM/action loss의 직접 gradient를 받지 않는다. 초기 Gumbel exploration과 score/diversity 경로가 coverage를 제공한다.
- voting row와 branch가 실제로 독립은 아니며 저자도 이를 approximation으로 제한한다.

### Appendix B — 재현 설정

- observation/state/action schema, augmentation, GELLO 수집 장치가 상세화된다.
- Table 9는 optimizer, schedule, EMA, selector hyperparameter를 제공한다.
- 4-step rectified-flow sampling, 10-action chunk, 10-step replanning을 사용한다.
- latency는 1,000 steps 평균이며 vision encode, selector, Florence forward, 모든 flow step을 포함한다.
- LightVLA와의 차이를 guidance source, hard-union/noisy-OR, diversity, global context 네 축으로 명시한다.

## 한계와 주의

1. **주요 capability gain은 작고 efficiency gain이 크다.** CALVIN Avg. Len.은 4.44→4.52, LIBERO Avg.는 96.9→97.7인 반면 latency는 52→22 ms다.
2. **MLP projector 결론의 범위가 좁다.** Florence-2-Large와 특정 projector 설정 하나에서의 결과다.
3. **selector complexity가 quadratic이다.** `O(N_v²D)`라 지금의 100/34 tokens에서는 싸지만 high-resolution/multi-camera scale에서 병목이 될 수 있다.
4. **실제 실험 범위가 작다.** 한 UR3 setup, rigid objects 세 종류, drawer, 약 120분 data뿐이다.
5. **control frequency와 synchronization이 없다.** latency를 deployment loop frequency로 바로 바꿀 수 없다.
6. **mask interpretability가 supervision되지 않는다.** action objective만으로 학습되어 background patch도 남긴다.
7. **실패는 contact/control 쪽에 남는다.** Fig. 10처럼 target을 봐도 misalignment와 obstacle collision이 발생한다.
8. **version drift가 있다.** project page v1과 PDF v2의 title, author list, CALVIN/LIBERO 수치, retained-token count가 다르다.
9. **공개 재현물이 없다.** code/checkpoint/data split이 활성 링크로 제공되지 않아 구현 주장을 독립 검증할 수 없다.

## 이 논문을 읽을 때 기억할 것

- contribution은 “state token을 하나 더 넣었다”가 아니라 **state가 perception compute allocation을 결정하게 했다**는 것이다.
- proprioception token 단독 이득은 4.44→4.45로 작다. 큰 이야기는 dual-query selection + global context + diversity의 조합이다.
- 12% token으로 full-token baseline보다 좋아진 것은 redundancy 제거가 regularization처럼 작동할 수 있음을 시사한다.
- “Think”라는 이름보다 실제 mechanism은 **proprioception-conditioned visual-token gating**으로 이해하는 편이 정확하다.
- 효율 평가의 핵심은 selector가 싸다는 것뿐 아니라, 뒤의 VLM과 cross-attention action head가 함께 짧아진다는 점이다.
