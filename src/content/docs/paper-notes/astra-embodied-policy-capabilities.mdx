## 한 줄 요약

범용 reasoning model이 숫자 action과 policy 보정을 만들 수 있음을 보여주지만, **유용한 task decision, 지속적인 contact control, 실제 시간 안의 실행, 성공 상태 검증은 각각 다른 능력**이라는 점을 드러내는 평가 연구다.

[Unexpected Robot Policy](../unexpected-robot-policy/)는 RoboDojo의 direct EEF target과 one-shot ICL, [GPT-Policy](../gpt-policy/)는 실제 로봇의 contextual demonstration/action alignment, [CodeActionBench](../codeactionbench/)는 geometry API·program·hidden verifier를 분석한다. [네 논문의 비교](../../topics/vla/#범용-모델을-policy로-쓰는-네-논문)에서 관측·controller·sample size 차이를 먼저 확인할 수 있다. 특히 Unexpected의 ICL 하락과 GPT-Policy의 개선은 같은 조건의 상반된 결과가 아니다.

## 문제의식

VLM이 로봇의 상위 계획을 만드는 것과 관측에서 직접 수치 명령을 구성하는 것은 다르다. 또 명령을 생성했다고 해서 그 모델이 grasp, 안정성, 전신 coordination을 모두 제공한 것도 아니다. 이 논문은 Astra가 무엇을 결정하고, interface·IK·PD·학습 policy·whole-body controller가 무엇을 대신하는지를 나눠 평가한다.

질문은 세 가지다. 첫째, 별도 학습 action policy 없이 관측과 feedback으로 명령을 만들 수 있는가? 둘째, 학습 policy의 proposal을 검토하고 필요한 부분만 보정하는 협력이 유용한가? 셋째, 실패 후 written guidance를 바꾸면 성공이 반복되고 다른 상태로 이전되는가? inference latency와 token 예산도 capability의 조건으로 다룬다.

이 연구는 새로운 end-to-end VLA를 학습하는 논문이 아니다. Astra의 weight는 고정하고, 도메인별 robot interface와 frozen policy/controller를 조합한다. prompt·tools·controller calibration이 바뀐 development trial은 고정 평가와 구분해야 한다.

## Method: 생성, 실행, 피드백의 분담

### Direct와 Hybrid

Direct는 현재 관측과 history에서 numerical command를 만든다. 하지만 raw torque를 언제나 직접 출력하는 것은 아니다. EEF target은 IK로 joint command가 되고, navigation의 forward는 simulator primitive가 실행한다. 따라서 Direct는 **학습 action policy가 없는 조건**으로 읽어야 한다.

Manipulation Hybrid는 다음 순서다.

1. 학습 policy가 action chunk를 제안한다.
2. Astra가 현재 이미지·state·instruction과 proposal을 검토한다.
3. proposal prefix를 승인하거나 bounded EEF/finger correction으로 교체한다.
4. 선택한 명령을 실행하고 새 관측을 얻는다.
5. task evaluator는 물리적 결과를 별도로 판정한다.

RoboDojo에서 승인과 correction은 같은 segment의 상호 배타적인 branch다. π0.5는 50-step proposal을 만들지만 승인 시 1–15 step만 실행하며, correction은 1–5 step이다. Direct도 1–5 step을 실행한다. model이 한 번에 긴 trajectory 전체를 실현하는 것으로 해석하면 안 된다.

RoboCasa는 proposal 검토에 더해 language subgoal rewriting을 허용한다. Humanoid Hybrid는 proposal gate와 다른 형태다. Astra가 velocity·sparse body target·dense reference를 지정하고 frozen controller가 전신 coordination을 제공한다.

### 경계와 시간 구조

RoboDojo는 25Hz, Direct target의 한 번 이동량은 5cm·회전량은 0.35rad safeguards다. humanoid의 whole-body controller는 50Hz이고 physics/joint control은 500Hz다. 이 숫자는 Astra inference frequency가 아니다. 여러 조건에서 physics를 추론 중 멈추므로 simulation time과 wall time을 반드시 나눠 본다.

<PaperFigure src="/astra-policy/figure-15.png" alt="Figure 15: episode 내부 action loop와 연구자 개발 loop" caption="Figure 15, p.25. within-episode feedback과 configuration 사이의 개발 loop를 구분한다. weight 업데이트나 autonomous recursive optimization을 입증하는 도식이 아니다." />

### Experience adaptation

SIMPLE의 Skill 문서는 task instruction, Memory 문서는 cross-episode note를 담는다. trial 후 관측과 action을 근거로 이를 수정하지만 Astra와 ScaleBFM weight는 고정된다. 성공 episode를 분석해 얻은 procedure도 repeat failure가 있어, 설명·진단·실행 개선·성공 유지가 같은 능력이 아님을 보여준다.

## Model Architecture와 Training Recipe

Astra의 내부 backbone, parameter count, pretraining loss, optimizer, training data composition은 이 논문에서 재구성할 수 없다. 모델 자체 구조를 추정하는 대신 외부 interface와 learned component의 역할을 정리한다.

| 구성요소 | 입력 → 출력 / 역할 | 학습·공개 범위 |
| --- | --- | --- |
| Astra | multimodal observation·history·tools → numerical target·승인·보정·guidance | 대다수 평가 xhigh reasoning; weight frozen. 일부 개발 기록 high |
| Gripper π0.5 | image·state·instruction → joint action chunk | RoboDojo task-finetuned; RoboLab DROID-trained zero-shot |
| Dexterous π0.5 | head+2 wrist RGB, 62D state → `50 × 62` | 1,000 demonstrations로 multitask full-parameter finetuning |
| ScaleTrack / ScaleBFM / Humanoid-GPT | reference 또는 velocity → coordinated body motion | frozen. command 성능과 pretrained controller 성능이 함께 반영됨 |
| In-hand RL | privileged state 또는 tactile/history → 22/16D joint action | task-specific frozen baseline. Astra와 관측·action rate 다름 |

Dexterous 62D action은 양손 wrist 각각 position 3 + rotation 6, finger 각각 22로 `2×(3+6)+2×22=62`다. 이미지는 640×360에서 aspect-ratio preserving padding을 거쳐 224×224로 바뀐다. wrist increment는 execution 전에 absolute pose로 복원한다.

| π0.5 multitask 학습 설정 | 원문 값 |
| --- | --- |
| 초기화·학습 | π0.5 base, full parameter, 50,000 optimization steps |
| Global batch | 256 |
| AdamW | β=(0.9, 0.95), ε=1e−8, weight decay=1e−10 |
| Gradient clipping | norm 1.0 |
| Learning rate | peak 2.5e−5, cosine decay to 2.5e−6 |
| Baseline 실행 | 30Hz, 50-step prediction의 첫 16 step 실행 후 재계획 |
| Hybrid 실행 | 1–16 policy step 또는 1–5 correction step; review/token exhaustion 시 π0.5-only fallback |

In-hand rotation RL actor/critic은 ELU MLP (512,256,128), 별도 running normalization이며 20Hz 22D action을 사용한다. PPO는 γ=.99, λ=.95, clip=.2, 5 epochs, 초기 adaptive LR 5e−4, target KL .01, value coefficient 2, entropy 0, gradient norm 1이다. cylinder는 4×8192 환경, H=16, 1,000 update; cuboid는 cylinder actor/normalizer 초기화 후 8192 환경, 4,000 update다. 각각 약 5.24e8 transition이다.

Rotation의 objective는 moving orientation target의 error를 줄이고 contact novelty와 action smoothness를 반영한다. 각속도는 별도 속도 reward보다 움직이는 target을 추종하면서 유도된다. `e(t)=2 arccos(|〈q(t),q*(t)〉|)`가 0.1rad 미만인 step 비율이 At-goal이다. 회전 목표가 한 바퀴 돌아 같은 orientation으로 돌아오면 정지한 object도 순간적으로 error가 작아질 수 있으므로 axial-speed MAE를 함께 봐야 한다.

Allegro translation baseline은 released tactile student checkpoint를 그대로 사용한다. 30-step joint history와 signed 3-axis tactile에서 8D latent를 추론하는 temporal Transformer와 (512,256,128) MLP가 16 joint action을 만든다. privileged PPO teacher의 action imitation으로 학습한 student이며 reward 직접 최적화와 구분한다. Translation+rotation은 released oracle에서 초기화한 privileged PPO teacher, 4096 환경, H=16, 20,000 update, 약 1.31e9 transition이다. 이는 범용 Astra와 training budget까지 맞춘 비교가 아니다.

### 1. Gripper: task에 맞는 motion prior가 있을 때 협력이 유리하다

| 평가 | Direct | Hybrid | π0.5 기준 |

RoboDojo Hybrid는 imitation sorting 53 대 0, tower 64 대 12, clothes folding 100 대 40, bottle disposal 100 대 36으로 Direct보다 높은 Score다. 반면 language classification은 Direct 60 대 Hybrid 38, object classification은 100 대 71이다. score와 binary success도 다르다. Organize Table은 Hybrid Score 60이지만 최종 success 0이다.

Hybrid executed step 42,750개 중 36,576개(85.6%)가 policy 그대로이고 6,174개(14.4%)가 Astra 생성·보정이다. **보정 step이 적다는 사실은 model request가 적다는 뜻이 아니다.** 모든 proposal을 검토하는 비용이 남는다.

RoboLab은 single-arm semantic pick/place 비중이 크고 zero-shot policy가 잘 맞지 않는 조건이다. Direct 98%라는 결과를 deformable/bimanual/contact-heavy task의 일반 성능으로 확대하면 안 된다. Appendix B는 Astra repeat attempts 허용, Blocks-in-Bin Direct 두 attempt의 decision budget 500(표준 180)을 명시한다. baseline은 정렬된 첫 5 run을 쓰므로 엄격한 동일 추론 budget 비교가 아니다.

### 2. Dexterous: local correction은 가능하지만 contact 재구성이 어렵다

Custom multitask benchmark의 Score는 π0.5 44.2, Direct 16.6, Hybrid 61.6이다. Hybrid는 Direct보다 10 task 모두 높고, policy보다 8 task 높으며 2 task는 같다. Mahjong storage는 +40점, upright egg +32점, bottle/can sorting +28점이다. Bread-slot insertion 28점과 nesting-doll 24점은 개선 뒤에도 낮다.

<PaperFigure src="/astra-policy/table-03.png" alt="Table 3: dexterous 열 task의 전체 Score" caption="Table 3, p.6. 0–100 partial-credit score이며 task success rate가 아니다." />
<PaperFigure src="/astra-policy/figure-03.png" alt="Figure 3: dexterous correction 원인과 실행 비율" caption="Figure 3, p.7. missed grasp/dropped object 33.33%, failed placement 20.90%가 주요 보정 원인. 88.02% step은 policy 그대로, 11.98%가 correction." />

이 평가의 internal score는 완전한 verification 성공 1, 종료 시 subgoal은 모두 만족하지만 verification 부족이면 .8, 일부 subgoal 만족이면 `.8k/K`, subgoal 없이 5cm lift만 있었다면 .1, 유효 progress가 없으면 0이다. task별 5 case 평균을 100배 한 뒤 10 task를 동일 가중 평균한다. 따라서 80점도 완전 success를 보장하지 않는다. placement는 hand contact 없는 release와 2초 stability, pot hold는 10cm lift와 3초 hold가 필요하다.

DexJoCo Hanoi stacking은 10개의 experience-guided trial 중 5 성공이다. dual Panda/Allegro, 50Hz, 최대 1,500 control step, segment당 최대 30 step이다. 5 pair 사이에 guidance가 수정되어 독립 zero-shot 10회가 아니다. published baselines는 rand-obj 50 episode를 세 set 평균하므로 sample size와 adaptation 조건을 맞춘 순위로 읽지 않는다. 11,320 step 중 policy 73.6%, correction 26.4%, 전체 기록 token 63.60M이다.

### 5. Locomotion: dense reference의 수치 일관성과 실제 시간 제약

PASSAGE의 scene-aligned representation과 frozen G1 ScaleTrack은 유지하고 learned motion generator만 Astra로 교체한다. 0.5초 reference는 50Hz 25 frame × 65 value = 1,625 value다. root height·projected gravity·planar velocity·yaw rate·29 joint position/velocity가 서로 일관되어야 한다.

한 course에서 PASSAGE는 13.18초에 goal 도달, final error .495m이다. Astra 다섯 순차 시도는 모두 goal 미도달이다. 첫 시도는 9.80초 후 fall, 중간 세 시도는 no-progress, 마지막은 30초 upright이지만 final error 6.519m, goal-distance reduction 2.598m이다. 마지막 travel 3.833m와 progress 2.598m도 같은 지표가 아니다. 다섯 번째에는 다른 course의 retargeted walking clip이 추가된다.

각 call 평균 latency 39.86초, 마지막 episode 250 synchronous calls, physics paused다. **30초 robot motion은 실시간 30초 실행 결과가 아니다.** joint limit 안에 있는 reference라도 root/limb evolution이 물리적으로 일관되지 않으면 제자리걸음·contact·fall이 생긴다.

Astra 없이 수행한 compact-interface 진단은 Five-point와 WholeBody-14 각각 6 course × 2 physics backend = 12 rollout이다. strict success는 upright, .2m endpoint, 5초 hold, tracked points within course, obstacle force 5N 이하를 요구한다. 둘 다 strict success 0; goal+stop만은 4/12와 3/12, fall 1/12와 4/12다. generator도 달라 dimensionality만의 causal ablation이 아니며 서로 다른 simulator의 force도 calibrated measurement로 직접 비교하지 않는다.

### 6. Humanoid: pretrained coordination 위의 decision과 stage transition

HumanoidBench 30 task, 각 seeds 1,2. Astra는 RGB에 더해 privileged state·task geometry·guidance를 받고 frozen Humanoid-GPT controller에 velocity 또는 sparse pelvis/wrist references를 준다. Run/Crawl/Stair는 calibrated gait generator가 phase·posture·limb coordination을 공급한다.

Maze mean return 1358.8은 threshold 1200을 넘지만 Reach 11430.2는 threshold 12000 미만이다. Run 642.1은 넘어지지 않아도 threshold 700 미만, Stair 272.5는 limited progress/retreat, Door 142.4는 usable passage를 만들지 못한다. Astra task mean 6개(Stand, Walk, Maze, Crawl, Push, Sit Simple)가 native threshold에 도달한다.

30 task native return을 동일 가중 평균하면 Astra 581.9, TD-MPC2 338.2, SAC 42.7, DreamerV3 −41.9다. 하지만 task별 reward scale이 다르므로 이 숫자를 통합 success rate로 읽지 않는다. 세 published reference 중 최고보다 높은 task는 13/30, Kitchen은 0 tie다. published baseline은 다른 training·controller 조건이며 Astra는 task당 두 seed만 사용한다.

Scripted Walk cadence 1.2→1.8Hz calibration은 eight paired seeds mean return 705.72→746.60으로 바꾼다. 따라서 높은 return은 model reasoning만 아니라 controller calibration도 반영한다. Push는 entry와 contact reference를 같이 바꾸면 4.97cm에 도달하지만 둘 중 하나만 바꾸면 36.81/23.11cm error다. body configuration과 contact geometry가 함께 맞아야 한다.

## 한계와 주의

- 평가의 많은 부분이 simulation과 paused physics다. native success와 real-world real-time deployability는 구분한다.
- task당 5 case, humanoid 두 seed, single-course sequential attempt 등 표본이 작거나 범위가 좁다. subset 성능을 전체 task distribution으로 확대하지 않는다.
- learned policy는 domain-specific training을 갖고, humanoid는 pretrained controller와 calibrated motion generator에 의존한다. model capability와 complete-system capability를 분리한다.
- same start라도 관측·history·action rate·harness·repeat allowance가 다를 수 있다. policy access만의 causal gain으로 읽지 않는다.
- 예측·오류 인식·수정·verification·success retention은 각각 평가해야 한다. intervention이 standalone success를 손상시키는 사례도 반드시 포함한다.
- 전체 control log와 simulator/checkpoint가 공개 코드에 모두 포함되지 않으므로 완전 재현 가능성을 단정하지 않는다. 공개 코드의 benchmark scope와 PDF scope도 다르다.
- paper project 링크는 이번 확인에서 접근하지 못했다. PDF와 접근 가능한 공개 code/report를 근거로 썼으며 접근 불가 페이지의 내용을 추정하지 않았다.

## Citation Trail과 후속 질문

[π0.5](../pi/pi05-open-world-generalization/)는 협력의 action prior, [ACT](../act-action-chunking-transformer/)와 [Diffusion Policy](../diffusion-policy-visuomotor-policy-learning/)는 action chunking과 temporal control의 비교 기준이다. [T-Rex](../t-rex-tactile-reactive-dexterous-manipulation/)는 빠른 contact feedback을 architecture 안에 두는 접근으로, 외부 reasoning correction의 지연 문제와 연결된다. [ECoT 계열](../ecot/)과 [Molmo 계열](../molmo/)은 reasoning representation을 학습 policy에 결합하는 흐름이다. [HOVER](../hover-humanoid-versatile-controller/)와 [OmniH2O](../omnih2o-humanoid-teleoperation/)는 humanoid controller가 어떤 motion prior를 공급하는지 읽는 배경이다.

후속 실험 제안은 논문 결과와 구분한다. 첫째, 동일 observation/harness/decision budget에서 no-policy·always-policy·selective-intervention을 비교하고 기존 success loss를 별도 metric으로 둔다. 둘째, paused와 unpaused execution을 나눠 feedback staleness·contact failure·wall-clock budget을 측정한다. 셋째, grasp 유지와 object motion progress, native success와 hold verification을 동시에 평가한다. 넷째, reflection 뒤 알려진 scene 반복·held-out state·held-out task에서 success retention을 별도로 측정한다.
