## 한 줄 요약

<SectionFeedback page="MolmoB0T" section="한 줄 요약" />

MolmoB0T는 real robot demonstration이나 task-specific fine-tuning 없이, MolmoSpaces 기반 procedural simulation으로 만든 1.7M expert trajectories만으로 Franka/DROID와 RB-Y1 조작에서 zero-shot sim-to-real transfer를 보인 open manipulation policy suite다.

## 문제의식

<SectionFeedback page="MolmoB0T" section="문제의식" />

기존 robot foundation policy는 대규모 real teleoperation data에 크게 의존한다. Open X-Embodiment, DROID, π 계열, GR00T 계열 모두 real robot trajectory나 real-like post-training data가 중요한 축이다. MolmoB0T가 던지는 질문은 더 좁고 공격적이다.

| 질문 | MolmoB0T의 실험적 답 |
| --- | --- |
| simulation만으로 manipulation policy를 만들 수 있는가 | 충분히 큰 scene/object/camera/action randomization이 있으면 pick-and-place와 articulated manipulation에서 real transfer가 가능하다고 주장한다. |
| sim-to-real gap은 photorealism으로만 줄이는가 | photorealism보다 procedural diversity, camera randomization, object/receptacle scale, action perturbation, image augmentation을 핵심 변수로 둔다. |
| 성능 향상이 architecture 때문인가 data 때문인가 | MolmoBot-Pi0로 π0 architecture를 맞춘 비교를 넣어 MolmoBot-Data 자체의 효과를 분리하려고 한다. |
| mobile manipulation까지 가능한가 | RB-Y1에서 door, drawer/cabinet open, mobile pick-and-place를 다루지만 real-world door result는 아직 작고 failure가 뚜렷하다. |

이 논문은 "simulation data가 real data를 보조한다"가 아니라 "simulation data가 main source가 될 수 있다"는 방향의 강한 benchmark paper다.

## 시스템 설정

<SectionFeedback page="MolmoB0T" section="시스템 설정" />

| 항목 | Franka FR3 / DROID setting | Rainbow Robotics RB-Y1 setting |
| --- | --- | --- |
| robot | 7-DoF Franka FR3 arm + Robotiq 2F-85 gripper, DROID-style setup | mobile manipulator, holonomic base 3-DoF, 6-DoF torso, 2-DoF head, dual 7-DoF arms, grippers |
| task | tabletop pick, pick-and-place, next-to placement, color-conditioned placement | pick, pick-and-place, drawer/cabinet open, door opening |
| observation | RGB cameras, proprioceptive state, language instruction, optional point conditioning | head/wrist RGB cameras, joint state, task language, optional 2D point conditioning |
| action | Franka action uses arm/gripper commands; paper emphasizes absolute action representation for real transfer | torso/arms/grippers and base velocity commands for mobile tasks |
| policy output | action chunk of 16 timesteps; simulation eval often executes 8 predicted actions at 100 ms each | action chunks; real door episodes use 100 ms inference timestep for safety |
| evaluation | held-out simulation houses/assets and real DROID environments | held-out simulation environments and small real door-opening trials |

### prior dataset과의 차이

논문 Table 2 기준으로 MolmoBot-Data는 DROID의 76k episodes/350 h/564 environments보다 훨씬 크고, Open X-Embodiment처럼 real multi-embodiment data를 모은 것이 아니라 synthetic environment diversity를 크게 키운다. RoboCasa-365도 simulation dataset이지만 500k episodes, 2,500 environments, 1 embodiment인 반면 MolmoBot-Data는 1.7M episodes, 94.2k environments, 2 embodiments, mobile manipulation을 포함한다.

### 데이터 schema와 loader 관점

공식 코드의 `MolmoBot/olmo/data/synthmanip_dataset.py`는 SynthManip-format HDF5와 mp4 video를 읽는다. 주석 기준 expected structure는 `{data_path}/{split}/house_*/*.h5`이고, H5에는 `traj_{i}/obs/sensor_data/{camera_name}`, `traj_{i}/actions/{action_key}`, `traj_{i}/obs_scene`, `traj_{i}/success`, `valid_traj_mask`, per-trajectory stats가 들어간다. dataset indexing은 timestep이 아니라 trajectory 기준이며, 각 `get()` 호출에서 trajectory 내부 timestep을 uniform 또는 grasp-aware weight로 sampling한다.

MolmoBot-Pi0 쪽 `MolmoBot-Pi0/molmobot_pi0/dataset_openpi.py`는 OpenPI data pipeline에 맞춰 `observation/exterior_image_1_left`, `observation/wrist_image_left`, `observation/joint_position`, `observation/gripper_position`, `action`으로 mapping한다. action horizon은 config에서 가져오고, selected action은 joint position action 또는 relative joint action으로 바뀔 수 있다.

## Method

<SectionFeedback page="MolmoB0T" section="Method" />

MolmoB0T의 method는 세 층으로 읽는 것이 좋다.

| 층 | 역할 | 핵심 설계 |
| --- | --- | --- |
| MolmoBot-Engine | synthetic expert data generation | MolmoSpaces house에서 task object/receptacle sampling, camera/scene/robot randomization, IK/CuRobo 기반 phase planner, 실패 시 retry/replan |
| MolmoBot-Data | behavior cloning corpus | RGB, proprioception, language, optional object point, action chunk를 포함한 1.7M expert trajectories |
| policy suite | 같은 data 위에서 architecture 비교 | MolmoBot, MolmoBot-Pi0, MolmoBot-SPOC 세 policy class를 학습 |

### expert trajectory generation

Franka task는 IK 기반 interpolation을 사용하고, RB-Y1은 CuRobo로 whole-body collision-aware trajectory optimization을 수행한다. Pick-and-place phase는 `Pregrasp -> Grasp -> Lift -> Preplace -> Place -> Postplace -> Stow`처럼 나뉘며, waypoint가 실패하면 현재 상태에서 다시 planning한다. RB-Y1 planning은 mobile base, torso, arm을 함께 고려하므로 단순 tabletop grasp보다 planning 문제가 더 크다.

### domain randomization

MolmoBot-Engine은 다음 축을 강하게 흔든다.

| randomization | 목적 |
| --- | --- |
| environment/object placement | scene layout과 object/receptacle 위치를 다양화 |
| camera pose | real camera calibration과 viewpoint mismatch 완화 |
| lighting/texture/material/dynamics | visual/physics gap 완화 |
| robot joint/action perturbation | expert trajectory 주변의 recovery behavior 학습 |
| image augmentation | ColorJitter, GaussianBlur, RandomPosterize, RandomSharpness, RandomGrayscale 등으로 sim-to-real 보강 |
| prompt randomization | language phrasing에 대한 robustness 확보 |

논문 ablation은 pick task에서는 house environment 수보다 trajectory count가 더 직접적인 성능 변수였다고 보고한다. 즉 모든 task에서 "환경 수를 무조건 늘리면 된다"는 결론은 아니다.

## Model Architecture

<SectionFeedback page="MolmoB0T" section="Model Architecture" />

![MolmoBot policy architectures](/molmobot/fig04-policy-architectures.png)

그림 출처: MolmoB0T paper Figure 4 crop.

### 세 policy class

| 모델 | 구조 | 의도 |
| --- | --- | --- |
| MolmoBot | Molmo2-4B 기반 multi-frame VLM + DiTX-style flow matching action head | main policy, 가장 높은 성능 목표 |
| MolmoBot-Pi0 | PaliGemma 3B + π0/openpi action expert 구조 | π0 architecture를 맞춰 data 효과를 분리하는 controlled comparison |
| MolmoBot-SPOC | SigLIP2 vision/text encoder + bidirectional transformer decoder + discrete action bins | lightweight/edge-friendly policy, future RL fine-tuning 후보 |

### MolmoBot

MolmoBot은 RGB image, language instruction, proprioceptive state, optional 2D point conditioning을 입력으로 받는다. 논문과 코드 기준으로 중요한 특징은 다음과 같다.

| 구성 | 내용 |
| --- | --- |
| VLM backbone | Molmo2-4B, image/text context encoding |
| action head | DiTX-based flow matching action head |
| action chunk | 16 timesteps |
| observation frames | single-frame `MolmoBot-Img`, multi-frame `MolmoBot (F=2)`, `MolmoBot (F=3)` variant |
| conditioning | action expert가 VLM hidden states를 cross-attention으로 참조 |
| state handling | 코드에는 `skip`, `zero`, `set_arm_zero`, `set_gripper_zero`, `cross_attn`, `self_attn` state mode가 있음 |

공식 코드 `MolmoBot/olmo/models/molmobot/molmobot.py`의 `MolmoBotConfig` 기본값은 `action_dim=7`, `action_horizon=16`, `n_action_steps=8`, `flow_matching_num_steps=10`이다. 실제 논문 task/robot별 action dimension은 config와 processor에 의해 달라질 수 있으므로, Survey에서는 이 값을 "공개 코드 기본 config"로만 읽는다.

### flow matching action head

`MolmoBot/olmo/nn/action_expert.py`는 `ActionExpert`를 DiT-style transformer로 구현한다. `ActionExpertBlock`은 self-attention, cross-attention, MLP를 가지고, continuous timestep embedding으로 AdaLN-Zero modulation을 한다. `molmobot.py`의 `_compute_flow_matching_loss()`는 다음 절차를 그대로 구현한다.

1. Beta distribution에서 flow timestep `t`를 sampling한다.
2. target action `a`와 Gaussian noise `z`를 섞어 `x_t = (1 - t) z + t a`를 만든다.
3. target velocity를 `a - z`로 둔다.
4. action expert가 VLM layer states와 state embedding을 condition으로 velocity를 예측한다.
5. predicted velocity와 target velocity의 MSE를 action flow loss로 계산한다.

Inference의 `generate_actions()`는 noise trajectory에서 시작해 `flow_matching_num_steps`만큼 Euler integration으로 action trajectory를 업데이트한다.

### MolmoBot-SPOC

`MolmoBot-SPOC/architecture/spoc_model.py`는 `SpocContinuousActionModel`을 정의한다. visual encoder가 camera별 visual token을 만들고, text/point token과 proprioception을 `ParallelActionDecoder`에 넘긴 뒤 `LinearActorHead`가 action logits를 낸다. 논문 설명처럼 continuous action을 256개 quantile bin으로 discretize해 cross-entropy로 학습하는 route와 연결된다.

## Training Recipe

<SectionFeedback page="MolmoB0T" section="Training Recipe" />

| 항목 | 내용 |
| --- | --- |
| 학습 목표 | synthetic expert trajectory behavior cloning |
| MolmoBot loss | flow matching velocity MSE over action chunks |
| MolmoBot-SPOC loss | quantile-binned discrete action classification |
| MolmoBot-Pi0 | openpi codebase를 사용해 π0 architecture와 비교 |
| Franka data mixture | Pick 20%, Pick-and-place Fixed Height 10%, Pick-and-place Random Height 35%, Pick-and-place-next-to 20%, Pick-and-place-color 15% |
| RB-Y1 data mixture | Multitask는 Open 20%, Door-open 20%, Pick 30%, Pick-and-place 30%; Door Specialist는 Door-open 100% |
| image augmentation | ColorJitter, GaussianBlur, RandomPosterize, RandomSharpness, RandomGrayscale |
| timestep sampling ablation | training에서 sample하는 denoising timestep 수 `T in {1,2,4,8}`를 비교 |
| action representation ablation | Franka FR3에서 absolute action과 delta action 비교 |

논문은 data generation과 policy training을 분리한다. MolmoBot-Engine이 expert trajectories를 만들고, policy는 그 결과를 behavior cloning한다. 따라서 "simulation에서 RL로 reward를 optimize했다"는 식으로 읽으면 틀린다. MolmoBot-SPOC는 향후 on-policy RL fine-tuning에 적합한 경량 구조로 제안되지만, paper의 주 실험은 imitation learning이다.

## Experiments and Results

<SectionFeedback page="MolmoB0T" section="Experiments and Results" />

### DROID real-world static manipulation

논문 main claim의 중심은 real DROID pick-and-place 평가다. 4개 환경, 40 tasks, policy당 120 episodes를 사용하며, task prompt에 맞춰 object가 receptacle 안/위에 안정적으로 놓이면 success로 친다. unsafe behavior나 horizon 내 미완료는 failure다.

| Model | Real success |
| --- | ---: |
| π0.5 | 31.3% |
| MolmoBot-Pi0 | 46.7% |
| MolmoBot-Img | 72.5% |
| MolmoBot (F=2) | 79.2% |
| MolmoBot (F=3) | 75.0% |

공식 technical website는 같은 DROID result를 2026-03 release narrative에서 `MolmoBot (F=2) 79.2%`, `π0.5-DROID 39.2%`로 설명한다. paper Table 6 crop은 `π0.5` real column을 31.3%로 보여주므로, 여기서는 paper table 값을 기준으로 두고 website/blog의 수치는 별도 release-page summary로 구분한다.

![MolmoBot main results](/molmobot/table06-main-results.png)

그림 출처: MolmoB0T paper Table 6 crop.

### DROID simulation held-out environments

Simulation evaluation은 task당 1000 episodes 기준이다. Pick-and-place류는 oracle success와 final success를 함께 보고한다. MolmoBot (F=2)는 average 64.1%로, π0.5-Finetune 36.0%, π0.5 zero-shot 10.0%보다 높다. 특히 Pick MSProc에서는 93.5%, Pick Classic에서는 66.8%, Pick Random-Cam에서는 63.7%를 기록한다.

해석상 중요한 점은 MolmoBot-Pi0가 평균 41.5%로 π0.5-Finetune 평균 36.0%보다 높다는 것이다. 같은 π0 계열 architecture를 synthetic MolmoBot-Data로 학습했을 때도 성능이 올라가므로, 논문은 data scale/diversity가 핵심 원인이라고 주장한다.

### restricted camera / RB-Y1 simulation

![MolmoBot restricted camera and RB-Y1 results](/molmobot/table07-08-restricted-rby1.png)

그림 출처: MolmoB0T paper Table 7, Table 8 crop.

Restricted camera setup에서는 single fixed-shoulder camera에 가까운 조건을 본다. Pick MSProc simulation에서는 MolmoBot (F=2)가 93.5%, MolmoBot-Img가 92.2%, MolmoBot-SPOC가 70.4%다. Pick Kitchen real 30 tasks에서는 MolmoBot-Img가 86.6%, MolmoBot (F=3)가 73.3%, MolmoBot (F=2)가 70.0%, π0.5가 63.3%다.

RB-Y1 held-out simulation에서는 MolmoBot Multitask가 Pick 44.8%, Pick & Place 22.5%, Open 25.2%, Door Open 70.2%를 보이고, Door Specialist는 Door Open 77.7%다. MolmoBot-SPOC는 Articulated에서 Open 21.8%, Door Open 58.8%로 낮지만 경량 policy라는 trade-off가 있다.

### real RB-Y1 door opening

Real-world door opening은 세 door 환경에서 9 trials만 수행됐다. 결과는 handle grasp 4/9, door opened 2/9다. Door 1/3에서는 handle이 오른쪽에 있는 configuration이 실패 원인으로 언급되고, Door 2는 세 번 모두 grasp를 성공했다. 여러 trial에는 hardware fault가 들어가므로 이 결과는 "mobile manipulation이 완성됐다"는 증거라기보다, sim-only policy가 real pull-door task에 부분적으로 transfer될 수 있다는 early evidence로 읽는 것이 안전하다.

### data ablation

![MolmoBot data scaling ablation](/molmobot/fig08-data-scaling.png)

그림 출처: MolmoB0T paper Figure 8 crop.

Figure 8은 pick task에서 data scale, object classes, environments를 바꾼다.

| Ablation | 관찰 |
| --- | --- |
| trajectory count | 10k -> 25k -> 50k로 늘릴수록 real/sim pick success가 대체로 증가한다. |
| object diversity | simulation performance에는 개선이 보이지만, DROID real subset은 evaluation objects가 제한적이라 trend가 덜 명확하다. |
| environment diversity | 50, 100, 5k, 50k environments 변화가 pick task 성능을 크게 개선하지 않는다. local tabletop pick에서는 background house diversity보다 interaction data scale이 더 중요할 수 있다. |

### model/action ablation

Figure 9는 timestep sampling `T`와 action representation을 비교한다. Simulation performance는 `T`가 커질수록 대체로 좋아지고 `T=8`에서 peak를 보지만, real-world subset은 `T=4`가 peak라 단조롭지 않다. Action representation은 Franka FR3 real setting에서 absolute action이 delta action보다 크게 좋고, simulation에서는 둘이 비슷하다. 이 차이는 sim metric만 보고 real transfer를 예측하기 어렵다는 점을 보여준다.

| SIMPLER reimplementation | DROID Franka setup으로 바꾼 zero-shot benchmark이며, benchmark-specific asset/task coupling 때문에 generalist policy 평가로는 한계가 있다고 논문이 직접 지적한다. |
| LIBERO-object reimplementation | distractor 유무에 따라 결과가 크게 달라지고, brand-name product appearance mismatch 같은 visual distribution issue가 남는다. |
| real evaluation institution | DROID evaluation은 여러 physical robot과 기관 환경을 포함하지만, public site에 private deployment detail로 확장해서 쓰면 안 된다. |

## 한계와 주의

<SectionFeedback page="MolmoB0T" section="한계와 주의" />

| 한계 | 설명 |
| --- | --- |
| simulation asset ceiling | MolmoBot-Engine은 simulator와 asset/library가 표현할 수 있는 object, articulation, contact에 묶인다. |
| real mobile manipulation evidence | RB-Y1 real door opening은 9 trials, opened 2/9로 작고 hardware fault가 섞여 있다. |
| task scope | manipulation/articulation 중심이며 navigation은 blog에서도 out of scope로 명시된다. |
| benchmark sensitivity | prompt phrasing, camera setup, final/oracle success 차이에 민감하다. |
| sim metric vs real transfer | environment diversity ablation과 action representation ablation에서 sim과 real trend가 완전히 같지 않다. |
| public reproducibility cost | code/data/model은 공개되었지만 1.7M trajectory 생성과 대규모 training은 A100급 compute와 simulator stack이 필요하다. |
| safety | unsafe collision은 failure로 처리하지만, real robot deployment safety controller와 fault handling은 policy 성능과 별개의 시스템 문제다. |

## 기억할 점

<SectionFeedback page="MolmoB0T" section="기억할 점" />

- MolmoB0T의 핵심 contribution은 "Molmo2 VLM" 자체보다 **simulation-only data engine + large-scale procedural diversity + controlled architecture comparison**이다.
- DROID real 결과는 강하지만, paper table과 website summary의 baseline 수치가 다르게 제시될 수 있어 출처를 분리해야 한다.
- MolmoBot-Pi0 결과는 data effect를 읽는 데 중요하다. 같은 π0-style architecture라도 MolmoBot-Data로 학습하면 π0/π0.5 baseline보다 강해진다는 것이 논문의 중요한 논리다.
- RB-Y1 real result는 조심해서 읽어야 한다. Simulation에서는 의미 있는 수치가 있지만, real pull-door opening은 아직 small-N evidence다.
- data ablation은 "scale matters"를 보여주지만, object/environment diversity 효과는 task와 evaluation object distribution에 따라 달라진다.
