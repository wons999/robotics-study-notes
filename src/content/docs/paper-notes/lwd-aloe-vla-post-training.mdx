## 먼저 보는 비교

**두 논문은 실제 로봇에서 모은 실패·성공·사람의 교정 경험으로 flow-based VLA를 개선한다. LWD는 여러 로봇의 공유 경험으로 하나의 generalist policy를 계속 갱신하는 시스템, ALOE는 현재 policy의 action을 제대로 평가하는 critic에 초점을 둔다.** LWD의 DIVL은 replay action-value 분포에서 optimistic quantile을 뽑고, ALOE는 현재 actor가 생성한 다음 action chunk로 TD bootstrap한다.

요청에 따라 두 논문을 이 페이지에 함께 정리했다. 앞의 안내와 뒤의 비교만 읽어도 차이를 파악할 수 있고, 각 논문 섹션에는 원문 방법·수식·데이터·recipe·모든 실험과 appendix를 포함했다. 두 논문의 Figure/Table 번호는 별도이므로 caption과 inventory에 항상 논문 이름을 붙였다.

| 질문 | LWD | ALOE |
| --- | --- | --- |
| 주요 문제 | heterogeneous fleet replay에서 안정적인 generalist RL과 deployment loop | replay의 과거 행동 가치와 현재 policy의 action 가치가 다름 |
| Value target | dataset action의 scalar Q 분포 → entropy-adaptive quantile | 현재 actor의 다음 chunk → current-policy Q의 TD target |
| Policy 개선 | fixed BC flow reference + critic action gradient의 QAM | replay action의 clipped advantage-weighted flow-matching |
| 수집 방식 | 16 actor의 비동기 수집·central learner·checkpoint redeploy | task별 human-in-the-loop collect → critic → actor의 iteration |
| 대표 결과 | 8-task 평균 score .95. grocery binary SR + long-task partial score의 혼합 | Phone/Laundry/Sorting/Assembly SR 80/58.7/87/95% |
| 관계 | offline-to-online implicit improvement와 fleet infrastructure | mixed replay에서 current-policy evaluation·action-level credit |

**LWD의 .95와 ALOE의 95%는 같은 지표가 아니다.** ALOE 95%는 Phone Assembly 한 task의 완료율이고, LWD .95는 서로 다른 rubric을 적용한 여덟 task의 평균이다. 두 논문 사이의 직접 head-to-head benchmark도 없다.

각 episode는 success/failure/timeout label을 갖고, 학습 reward는 **성공 terminal에서1, 그 외0**이다. action chunk 안의 per-step reward를 discount해 chunk reward `r̄_t`로 만든다. 이후 TD는 step-count에 맞춰 `γ^H`를 사용한다. evaluation의 단계별0/0.5/1 credit은 training reward와 다른 계약이다.

공개 논문이 보장하는 transition은 `(s_t, a_t:t+H, r̄_t, s_t+H)`이며 state는 image/proprio/instruction, action은 실제 실행한 chunk다. 원시 파일 key·정확한 joint/gripper 순서·단위·normalization stats·episode filtering 구현은 공개 학습 코드로 확인할 수 없다. operator가 필요한 correction을 판단하는 human-in-the-loop 수집이지, 모든 reset·reward·교정이 자동이라는 뜻은 아니다.

### Method: DIVL이 무엇의 분포를 배우는가?

IQL은 dataset action들의 Q를 높은 **expectile**에 맞춰 scalar V를 학습한다. DIVL은 같은 상태에서 replay action에 부여된 **scalar Q의 분포**를 categorical V로 학습하고 그 분포의 **quantile**을 bootstrap 값으로 선택한다.

```text
pψ(v | s) = distribution of Q̄(s, a), for a ~ D(· | s)
V loss = E_D[-log pψ(Q̄(s, a) | s)]
y_Q = r̄_t + γ^H Quantτ(Vψ(s_t+H))
Q loss = E_D[(Q(s_t, a_t:t+H) - y_Q)^2]
```

<PaperFigure src="/lwd/figure-02.png" alt="LWD Figure 2: offline/online의 공통 DIVL+QAM objective, actor와 공유 V/Q backbone, 온라인 replay1:1." caption="LWD Figure 2 · PDF v4 p.5. offline/online의 공통 DIVL+QAM objective, actor와 공유 V/Q backbone, 온라인 replay1:1." />

여기서 distributional V는 current-policy action을 샘플링한 평균 Vπ와 다르다. 확률적 rollout return 전체 `Zπ(s,a)`를 직접 학습하는 것도 아니다. 원문의 Eq.11은 **replay 행동 분포를 scalar critic Q로 보낸 pushforward distribution**이다. TD target은 explicit `max_a Q`나 현재 actor의 OOD candidate를 조회하지 않고 data-supported 높은 quantile을 선택한다.

Appendix A.1은201개 atom을[-0.1,1.1]에 놓는다. EMA Q target을 support에 clip하고 C51 방식으로 인접한 두 atom에 선형 배분해 cross-entropy를 계산한다. quantile은 cumulative probability가τ 이상인 첫 atom이다. Q critic은 scalar double-Q이며 categorical output은 state-value head V에 있다.

**Optimism은 entropy로 조절한다.** normalized entropy `Hnorm = -sum p_c log p_c / log C`에 대해 `τ(s)=clip(τbase - α·Hnorm(s), τmin, τmax)`를 사용한다. distribution이 퍼지면τ를 낮추고, 집중되면 더 높은 bootstrap 값을 선택한다. TD target의 τ는 stop-gradient로 취급한다. 이 entropy는 학습된 분포의 분산/혼합성을 나타내는 heuristic이며 calibrated epistemic uncertainty의 보장은 아니다.

Appendix A.2의 Proposition1은 이상적인 capacity·충분히 세밀한 discretization에서 **분포를 학습한 뒤 특정 asymmetric statistic을 추출하는 방법**과 **같은 asymmetric loss를 직접 최소화하는 방법**의 최적 scalar가 같음을 보인다. p=2는 expectile, p=1은 quantile이다. 동일τ에서 expectile과 quantile이 서로 같거나 finite201-atom 구현의 정확한 equality·online 안정성이 증명된 것은 아니다.

### Method: chunk backup과 QAM policy extraction

offline long task에는10-step **chunk-level** TD를 사용한다. H=30이므로 최대300 control step의 reward를 한 backup에서 전달한다. grocery는1-step chunk TD다. terminal이 window 안에 있으면 bootstrap을 제거한다.

online에서는 모든 task에1-step chunk TD를 사용한다. 인간 intervention이 끼어드는 heterogeneous trajectory에서 긴 backup이 한 policy의 연속 실행을 대표하지 않을 수 있다는 저자의 설명이다. 이는 관찰에 기반한 설계 이유이며 intervention crossing이 원인임을 분리한 별도 ablation은 아니다.

QAM의 개선 목표는 fixed BC reference `πβ`를 기반으로 `π*(a|s) ∝ πβ(a|s) exp(Q(s,a)/λ)`를 만든다는 KL-regularized 형태다. flow를 끝까지 unroll해 actor parameter로 역전파하면 비용·수치 불안정이 크므로, reference trajectory endpoint에서 **action gradient**를 구하고 adjoint dynamics로 local regression target을 만든다.

```text
Fixed reference: fβ = demonstration-BC flow before offline RL
Terminal adjoint: g̃_1 = -∇_a[Q(s, a_1) / λ]
Local actor objective: integrate ||2(fθ-fβ)/σ_w + σ_w g̃_w||² over flow time w
```

λ=2이며 reference fβ는 offline/online 전반에 고정한다. DIVL은 replay-supported bootstrap을 사용하지만 QAM은 **reference-generated endpoint의 critic gradient**를 조회한다. 따라서 LWD가 어떤 단계에서도 생성 action의 critic을 전혀 query하지 않는다고 설명하면 안 된다.

Algorithm1의 runtime은 BC reference 초기화 → offline learner update → actor rollout/intervention 저장 → offline/online 혼합 learner update →50-step publish다. Algorithm2는 V target fit → quantile TD → Q update·EMA → reference flow rollout·endpoint gradient → adjoint regression 순서다. Algorithm2 line7의 endpoint 표기 `a¹_t=a_t`는 reference 생성 action과 replay action의 변수 구분을 충분히 드러내지 않는다. source code가 없어 그 assignment의 실제 구현은 확인하지 못했다.

### Model Architecture와 Training Recipe

| 구성·학습 | 확인된 설정 |
| --- | --- |
| Actor | π0.5-style PaliGemma: Gemma2B + SigLIP, Gemma300M action expert |
| Value/critic backbone | shared Gemma3-270M-IT + SigLIP-So400M, readout-token state representation |
| V head | 201 categorical atoms[-.1,1.1], Q target의 C51 projection |
| Q head | action temporal attention pooling + state feature → 두 scalar head, clipped double-Q의 minimum |
| Offline RL | actor와 value/critic 모두 fine-tuning |
| Online RL | actor의 VLM 고정·action expert만 update. value/critic은 계속 전체 fine-tuning |
| Policy optimizer | AdamW, base lr2e-5, cosine decay |
| Value/Q optimizer | Adam, base lr5e-4, cosine decay |
| TD | γ=.9999; offline long n=10/grocery n=1, online n=1 |
| Adaptiveτ | offline τbase=.6, online .9, α=.3. τmin/max 구체값은 Appendix B2에서 미명시 |
| Replay·EMA | offline/online 약1:1, EMA rate .005로 설명 |

### Baseline budget·ablation·value diagnostics

SFT는336.6h demo만 학습하고 LWD는 전체652.5h의 실패/play를 활용한다. RECAP은 같은 value backbone의 state-value head로 lookahead advantage를 만들어 top30% positive와 human correction을 advantage condition에 사용한다. HG-DAgger는 demo와 online correction/rollout을 모방한다. policy optimizer·schedule을 맞췄지만 학습 신호와 활용 데이터는 다르다.

본문은 각 online method에4h·약60 robot-hours를 배정했다고 설명한다. Appendix C의 RECAP recipe는 **두 rollout round에 각각 약60 robot-hours**라고 기록한다. 이 관계가 불명확하므로 모든 baseline의 interaction budget이 정확히 같다고 단정하지 않는다.

scalar expectile → DIVL의 long-score는 offline .72→.79, online .78→.91다. Table II의 **+9.7%/+16.7%는 relative improvement**이며 absolute는+7/+13 percentage points다. Table V의 task별 결과에서는 모든 cell이 개선된 것은 아니다. 예를 들어 Freezer offline 1.00→.92, online .92→.97이다.

### Reward: terminal success0, intermediate-1

네 task 모두 성공 terminal은0, intermediate는-1, 실패는 `-Cfail`이다. `Cfail`은 task의 평균 trajectory length로 설정해 실패 penalty를 통상 unsuccessful rollout 길이에 맞춘다. 이는 LWD의 sparse binary0/1 terminal reward와 다르며 **성공 여부뿐 아니라 시간 비용**도 학습 신호에 들어간다.

failure trigger에는 empty grasp·object drop·insert/placement error·collision·timeout이 있다. Laundry는 충분히 펴지 않은 채 접기·여러 layer grasp·반복 shaking·다시 펼치기도 failure로 분류한다. 성공/실패 판정은 사람의 감독과 task 규칙을 사용하며 learned policy가 자동 safety certificate를 갖는다는 뜻은 아니다.

### Method: data-policy value와 current-policy Q

MC state-value는 replay episode return을 맞추고, replay next-action을 쓰는 SARSA-style TD는 implicit mixture behavior `πD`의 가치를 맞춘다. πD에는 사람과 여러 old checkpoint가 섞여 실제 하나의 executable checkpoint가 아닐 수 있다.

ALOE는 replay의 state/action/transition을 사용하되, **다음 action을 current actor πθ에서 다시 생성**한다. chunked action-value는 지금부터 h개의 control step 동안 정확히 주어진 action sequence를 실행하고, 그 뒤 current policy를 따르는 return을 목표로 한다.

```text
A_t = [a_t, ..., a_t+h-1]
y_t = sum(k=0..h-1) γ^k r_t+k
      + γ^h (1-d_t+h-1) E_A'~πθ(·|s_t+h,ℓ)[Q_target(s_t+h,A',ℓ)]
Lcritic = mean_i E_D[(Q_i(s_t,A_t,ℓ)-y_t)^2]
Q_pess(s,A,ℓ) = min_i Q_i(s,A,ℓ)
```

chunk 내부 action은 실제 실행한 segment에서 가져오고, 그 다음 bootstrap action은 current actor에서 가져온다. `A'`를 buffer의 과거 next action으로 바꾸면 다른 target이 된다. Q-chunking은 중간 reward와 전체 실행 action sequence를 함께 조건화한다. ordinary one-step state-value의 시간 간격만 늘리는 방법과 구분해야 한다.

h=50, critic 기본 K=2다. minimum aggregation은 policy extraction에서 명시적으로 사용하며, weakly covered/OOD action의 과대평가를 줄이려는 선택이다. Eq.4는 target을 `Qϕ−`로 표시하지만 bootstrap에서 ensemble을 정확히 어떻게 조합하는지, 기대값에 몇 개의 actor sample을 쓰는지까지 공개하지 않는다. minimum은 보수적 heuristic이며 모든 state에서 보장된 lower confidence bound는 아니다.

### Method: clipped advantage와 weighted flow loss

current-policy baseline은 **동일 state**에서 current actor의 action chunk를 샘플링하고 pessimistic Q를 평균한 것이다. 별도의 MC progress value와 다르다.

```text
Vπ(s,ℓ) = E_A'~πθ[Q_pess(s,A',ℓ)]
Aπ(s,A,ℓ) = Q_pess(s,A,ℓ) - stopgrad(Vπ(s,ℓ))
w = exp(clip(Aπ/β, -εclip, εclip))
Actor update = replay action에 대한 weighted flow-matching regression
```

β=.5다. replay action의 상대적인 품질로 weight를 바꾸므로 실패 trajectory를 통째로 버리는 학습이 아니다. weight clipping은 특정 sample의 영향력을 제한한다. PPO의 policy-ratio clipping과 같은 연산이 아니고, 매 update의 KL radius를 직접 측정한 것도 아니다.

continuous flow policy의 exact log-likelihood를 계산하기 어려워 negative flow-matching objective를 proxy로 사용한다. 원문 Eq.7의 noised action은 `ã=ηA+(1-η)ε`, loss는 `w·||ε-A-fθ(ã,s,ℓ)||²`다. η는 uniform time, ε는 Gaussian noise다. 여기서는 원문 target 부호를 유지했다. 실제 time axis/reverse-flow convention과 time embedding은 공개 코드로 확인하지 못했다. **weighted flow loss는 surrogate이며 exact weighted log-likelihood를 수치 계산한 결과가 아니다.**

critic과 actor는 이전 iteration의 weights에서 계속 fine-tuning한다. Algorithm1은 round마다 collect/human-correct → critic 10000 updates → actor 5000 updates → 새 policy로 다음 round 순서다. 매 actor gradient step마다 critic을 새로 학습하는 것은 이 알고리즘에 없다. 따라서 current-policy Q는 critic의 추정 목표이며, actor의 모든 update 순간에 이미 완벽하게 갱신된 Qπ가 있다는 보장은 아니다.

Appendix8.7의 unclipped KL 해는 `π*(A|s) ∝ πref(A|s) exp(Q(s,A)/β)`다. 여기서 πref는 **replay가 유도한 implicit behavior distribution**이다. 같은 state의 Vπ(s)는 action과 무관한 상수이므로 unclipped advantage weighting의 공통 normalizer만 바꾼다. exact likelihood·unclipped 이상적 objective의 정리를 finite clipped weighted-flow surrogate로 그대로 확장해 exact KL·매 update의 monotonic return을 보장할 수 없다.

저자들은 human supervision/reset 의존을 한계로 밝히고 자동 reset을 후속 방향으로 제시한다. current-policy bootstrap은 target mismatch를 줄이려는 방법이지만 bootstrapping·off-policy data·function approximation의 deadly triad를 제거하지는 않는다. ensemble의 효과는 실물 evidence이며 모든 추정오차에 대한 면역 증명이 아니다.

## 두 논문의 비교와 연관성

### 공통 기반과 직접 관계

둘 다 pretrained flow VLA, replay의 실제 action/observation/outcome, human correction과 TD critic으로 target-task 능력을 개선한다. value learning과 policy extraction을 나누고, RECAP/DAgger 계열과 비교한다. 실패 데이터는 버려야 하는 demonstration만이 아니라 value learning에 쓸 수 있는 경험이다.

ALOE 최초 공개는2026-02, LWD는2026-05다. 공통 AgiBot 배경은 있지만 저자 목록이 다르고, 검토한 LWD v4/ALOE v3의 참고문헌에는 **서로 직접 인용한 기록이 없다**. 방법론의 연관성을 비교할 수 있으나 이미 입증된 “ALOE→LWD 업그레이드”나 같은 model series로 분류하지 않는다.

### Value·support·policy update의 차이

| 차원 | LWD | ALOE | 의미 |
| --- | --- | --- | --- |
| 추정 대상 | replay action의 Q 분포 → optimistic statistic | 주어진 chunk 실행 후 current policy의 Qπ | implicit improvement bootstrap과 current-policy evaluation target의 차이 |
| 다음 target | Quantτ(V(s_next)) | A_next~πθ의 Q_target | LWD는 explicit next-action query를 피하고 ALOE는 current candidate의 coverage 위험을 처리 |
| Distributional 위치 | state-value201 atoms, scalar double-Q | scalar Q ensemble; AWR baseline은256-bin MC value | 단순히 distributional 유무만으로 나눌 수 없음 |
| 보수/낙관 기제 | double-Q min + entropy-adaptive quantile | ensemble min + bounded advantage weight | minimum과 upper quantile은 서로 다른 위치에 작용 |
| Actor 신호 | action gradient→adjoint local regression | Q−current-policy baseline→weighted replay flow | 생성 action의 gradient 개선과 기존 action reweighting의 차이 |
| Reference | fixed demo-BC flow fβ | KL 정리의 implicit replay πref; baseline은 current actor 평균 Q | 같은 reference라는 단어도 distribution이 다름 |
| Online schedule | asynchronous actor/learner·50-step fanout | collect quota→10000Q→5000actor→다음 round | streaming과 iterative collect/train의 stale-model 구조가 다름 |
| Fine-tuning | offline full; online actor VLM 고정 | vision encoder 외 actor 전체 | 성능 차이를 critic 하나에만 귀속할 수 없음 |

**flow likelihood에 관한 관계:** LWD는 exact likelihood와 full-generation backprop의 어려움을 QAM의 동기로 든다. ALOE도 exact continuous likelihood를 계산하기 어렵다고 인정하면서 weighted flow surrogate를 선택한다. 서로 다른 최적화 경로이며 모순이 아니다. AWR 계열로 flow VLA를 전혀 학습할 수 없다고 해석하면 안 된다.

**off-policy에 관한 관계:** 둘 다 다른 behavior의 데이터를 재사용하지만 target이 같다며 묶을 수 없다. 기재된 γ를 그대로 적용하면 한 chunk의 discount도 LWD `.9999^30≈.9970`, ALOE `.99^50≈.6050`으로 다르다. reward 정의와 step 단위를 맞추지 않고 return 크기를 직접 비교할 수 없다. LWD의 offline-to-online은 경험 유입·policy improvement 흐름을, ALOE의 off-policy evaluation은 current policy에 맞추려는 평가 대상을 강조한다. 최신 checkpoint의 데이터만 남겨도 human segment·truncation·weak action coverage까지 자동 해결되지는 않는다.

### 후속 연구로 연결하는 방법

다음은 **이 페이지의 추론·실험 제안이며 두 논문이 검증한 결합 시스템이 아니다**.

1. **ALOE를 LWD형 fleet infrastructure에서 평가한다.** episode versioning·snapshot consistency·checkpoint fanout은 current-policy critic에도 필요하다. next-action sampling·actor/critic lag·human chunk·task별 shape/normalization을 맞춰야 하므로 loss 이름만 바꾸어 같은 시스템이라 할 수 없다.
2. **Actor extraction을 따로 비교한다.** 동일 critic/data/reward에서 QAM 대 clipped weighted-flow를 비교하고, actor를 고정해 DIVL 대 current-policy bootstrap을 비교해야 value target과 actor update의 효과를 분리할 수 있다.
3. **Current-policy evaluation에 distributional 표현을 검토한다.** return distribution/ensemble uncertainty를 연구할 수 있지만 ALOE target을 DIVL quantile로 그대로 치환하면 추정 policy/statistic도 바뀐다. 원래 Qπ 계약이 유지된다고 자동 간주하지 않는다.
4. **Long-task 평가를 보강한다.** strict completion, partial score, reset 포함 wall-clock throughput, operator 공수, raw attempt와 seed/CI를 함께 보고해야 평균값이 precision placement·장기 신뢰성 차이를 가리지 않는다.

“혼합 데이터에서 어느 action chunk를 더 학습할 것인가”가 질문이면 ALOE를 먼저 읽고, “여러 robot의 task experience를 shared learner로 모아 계속 redeploy하는 구조”가 질문이면 LWD를 먼저 읽는다. 실제 알고리즘 선택은 조건을 맞춘 실험이 필요하다.

## Citation Trail과 사이트 내 읽기
